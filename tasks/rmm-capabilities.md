# RMM 能力建设计划

状态：待实施。日期：2026-11-03。

## 目标与范围

将现有 Web 远程管理控制台逐步扩展为支持持续监控、策略管理、自动化处置和规模化运维的 RMM。本文依据本次用户确认的十二项能力编写，需求编号 RMM-001 至 RMM-012 保持稳定。

本文是需求与实施计划，不代表功能已经实现或通过真实设备验收。本次仅交付文档，不变更业务代码。Web 为主要交互入口；持久化、调度、采集、授权与隔离需要服务端或 Agent 支撑，不能仅在浏览器实现。

## 现状与架构约束

- 当前项目已有控制客户端、共享状态及 Relay 实现，Web 接入远程桌面、终端与文件能力；具体可用范围仍需逐项核查源码与测试。依据：根 README.md、docs/development.md。
- 后续实施需先盘点已有模块，复用现有设备、权限、事件、报表和任务能力，不将本需求清单直接等同于全部缺失。
- 协议与资源 API 放入 control-client，缓存和事件绑定放入 shared-state，远程数据通道放入 relay，Web 负责呈现与交互。
- 浏览器沿用同源 Cookie 会话；服务端负责最终授权，任务执行不能依赖浏览器持续在线。
- MeshCentral 固定为 1.1.54。新增能力先核实 docs/meshcentral 的版本与协议证据；不假定上游已提供补丁、调度或监控 API。
- 仓库规范引用的 docs/plan/README.md 与 docs/plan/architecture-guardrails.md 在本次工作树不存在。本文按用户要求放在 tasks，不恢复或重建旧计划，也不变更既有阶段编号。

## 需求与验收

### RMM-001：监控与告警中心（P0）

- 范围：CPU、内存、磁盘、服务、设备离线规则；配置阈值、持续时间和作用范围，区分正常、异常与数据未知。
- 流程：采集 → 持续条件判定 → 告警去重 → 通知 → 确认或升级 → 恢复；维护窗口支持静默，保留处理记录。
- 验收：短暂波动不触发持续条件告警；同一异常不重复生成未恢复告警；恢复后保留时间线；确认、静默及升级均有可查询记录。
- 依赖：服务端采集与历史存储、规则执行器、通知渠道。

### RMM-002：策略中心（P0）

- 范围：按组织、设备组、操作系统分配监控、补丁和脚本策略；支持继承、例外、版本及设备最终生效配置。
- 流程：编辑 → 校验冲突 → 发布 → 计算生效配置 → 下发 → 回报应用结果。
- 验收：设备展示配置来源及覆盖关系；冲突有明确提示；策略变更后可以追踪哪些设备已应用、待应用或失败；旧版本可恢复。
- 依赖：统一设备归属与策略模型；继承顺序和冲突规则需在实现前确定。

### RMM-003：持久化自动化任务（P0）

- 范围：定时、事件触发、离线待执行、超时重试、并发限制、取消和执行历史；记录发起人、目标、参数及逐设备结果。
- 流程：创建 → 服务端持久化 → 调度 → Agent 执行 → 回传结果；明确排队、运行、成功、失败、超时、取消状态。
- 验收：关闭浏览器后任务继续；服务重启后可恢复待执行任务；离线设备上线后按有效期执行；重试不重复产生不可控副作用；部分失败可逐设备追踪。
- 依赖：持久化存储、调度执行器、幂等与重试约定、Agent 回执。现有前端任务展示应与服务端任务状态对接。

### RMM-004：补丁管理（P0）

- 范围：系统和第三方软件补丁扫描、审批、拒绝、分批发布、维护窗口、重启策略、失败追踪与合规报表。
- 流程：扫描 → 评估 → 审批 → 试点 → 扩大发布 → 校验安装及重启状态。
- 验收：能区分待审批、待安装、安装失败、待重启与已安装；未审批补丁不自动发布；窗口外不执行受限操作；试点失败可暂停后续批次。
- 依赖：各操作系统的补丁执行机制、第三方软件目录与许可。支持平台矩阵需先确定，不承诺所有补丁均可回滚。

### RMM-005：脚本库与软件部署（P1）

- 范围：脚本版本、参数、执行权限与历史；软件包安装、升级、卸载、检测规则和结果查询。
- 流程：入库 → 审核或授权 → 选择目标 → 调度执行 → 检测目标状态 → 保存结果。
- 验收：历史任务可定位具体脚本或软件版本；无权限用户不能执行；已安装软件按检测规则跳过；安装返回成功但检测失败时不能标为部署成功；敏感参数不明文进入日志。
- 依赖：RMM-003、文件或软件包存储、平台执行适配。

### RMM-006：资产管理深化（P1）

- 范围：全局软硬件清单、软件版本分布、资产变更记录、自定义字段、保修和生命周期。
- 流程：采集 → 标准化 → 与上一快照比较 → 更新清单及变更记录。
- 验收：支持按软件及版本筛选设备；硬件或软件变更可追溯；自定义字段支持校验与权限控制；展示最近采集时间，旧数据不被误判为当前状态。
- 依赖：资产采集、历史快照和字段模型；保修数据来源需另行核实。

### RMM-007：运维总览与历史指标（P1）

- 范围：异常设备、待处理告警、失败任务、历史趋势与设备健康详情；支持按授权范围和时间过滤。
- 流程：汇总指标 → 定位异常 → 跳转设备、告警或任务 → 查看处理结果。
- 验收：汇总与明细使用一致口径；无数据、采集失败与正常状态明确区分；趋势显示采样时间和缺失区间；越权设备不计入用户可见统计。
- 依赖：RMM-001、RMM-003 与历史指标存储；采样周期、保留期和健康评分口径待确定。

### RMM-008：安全与审计闭环（P1）

- 范围：完整登录恢复、会话列表与吊销、敏感操作授权、可检索和导出的操作审计。
- 流程：认证或恢复 → 权限校验 → 敏感操作确认或审批 → 执行 → 服务端记录审计。
- 验收：受支持的认证方式均有可用登录路径；吊销会话后不能继续使用受保护接口；审计能关联操作者、目标、动作、时间及结果；导出遵循权限且不泄露凭据。
- 依赖：认证插件、服务端会话控制及审计存储。具体缺口须重新核查，阻断登录或越权问题应优先修复，不受 P1 排期限制。

### RMM-009：部署与 Agent 生命周期（P1）

- 范围：集中下载安装包、批量部署、失败排查、版本与升级、长期离线设备清理。
- 流程：选择平台与分组 → 生成部署材料 → 安装注册 → 检查上线 → 维护升级或退役。
- 验收：安装包对应明确平台和目标分组；失败阶段可定位；升级结果逐设备可查；清理前可预览目标并确认，规则不误删短期离线设备。
- 依赖：上游 Agent 分发与升级机制、注册权限、部署工具；清理规则需明确保留审计和资产记录的方式。

### RMM-010：客户／站点管理（P2）

- 范围：面向 MSP 的客户、站点、权限与数据隔离，支持客户级策略和报表。
- 流程：建立客户与站点 → 分配设备及人员 → 应用策略 → 按客户查看运维结果。
- 验收：客户之间不能通过接口、搜索、统计或导出获取对方数据；客户和站点归属变更有记录；策略继承与 RMM-002 一致。
- 依赖：租户模型及服务端隔离。是否面向 MSP 为待确认产品范围，设备分组不能直接视为租户隔离。

### RMM-011：工单和外部集成（P2）

- 范围：告警转工单、责任人、处理记录、Webhook、邮件及协作工具通知。
- 流程：告警 → 创建或关联工单 → 分派 → 处理 → 恢复与关闭同步。
- 验收：同一告警重试不会重复建单；投递失败可查询和重试；外部恢复或关闭事件按约定同步；通知配置与密钥仅由授权人员管理。
- 依赖：RMM-001、通知网关及目标系统 API；优先选定实际使用的集成对象，再核实接口、签名和限流。

### RMM-012：安全、备份与网络设备集成（P2）

- 范围：汇总杀毒、磁盘加密、备份状态；按需求支持 SNMP 等无 Agent 设备监控。
- 流程：连接数据源或探针 → 发现及关联设备 → 标准化状态 → 异常告警与详情跳转。
- 验收：未知或过期状态不会显示为安全、加密正常或备份成功；采集失败可诊断；网络设备告警可追溯到探针及原始指标；凭据不返回浏览器。
- 依赖：安全和备份厂商 API、网络探针、设备凭据存储。首期以状态集成为目标，备份恢复或安全处置需另行明确范围。

## 实施阶段与任务映射

所有任务均未开始；以下顺序为建议，优先级沿用用户清单。

| 阶段          | 任务                                     | 交付与退出条件                                                       |
| ------------- | ---------------------------------------- | -------------------------------------------------------------------- |
| A：基线核查   | 核查 RMM-001～012 的源码、测试及协议能力 | 形成已支持、部分支持、需扩展清单；明确服务端归属、数据模型和平台范围 |
| B：监控基础   | RMM-001、RMM-002、RMM-003                | 完成规则、策略、任务最小闭环，验证浏览器关闭和服务重启场景           |
| C：批量维护   | RMM-004、RMM-005、RMM-009                | 完成试点设备的扫描、审批、部署、升级及失败追踪                       |
| D：运营与治理 | RMM-006、RMM-007、RMM-008                | 资产、指标和审计可追溯，认证恢复及会话吊销可验证                     |
| E：扩展       | RMM-010、RMM-011、RMM-012                | 按明确的客户模型及集成对象完成隔离和集成验收                         |

各阶段先实现服务端或 Agent 所需能力及资源 API，再完成状态绑定与 Web 页面。阶段 B 的策略先承载监控和任务配置，阶段 C 再加入补丁及软件策略。

## 数据、兼容与回退

- 建议持久化实体：规则、告警、策略版本、任务定义、逐设备执行记录、资产快照、审计事件；表结构、存储引擎和 API 在基线核查后确定。
- 新增接口应版本化或保持既有调用兼容；旧 Agent 不支持的能力应明确显示不可用，不伪造成功结果。
- 数据迁移先在测试环境验证并备份；服务回退需保留已产生的任务、执行及审计记录。
- 策略或自动化发布支持暂停新调度；已执行操作是否可逆由具体动作决定，不默认自动重试或回滚补丁、卸载和重启。

每个需求完成时记录验证命令、结果、平台与未验证条件，再标记完成。本文仅文档交付，不代表上述检查已执行。

实现前需确定：首批操作系统与版本、设备规模目标、服务端扩展方式、指标与审计保留期、维护窗口时区、策略冲突规则，以及是否面向 MSP。未确定项不作为当前已支持能力或性能承诺。
