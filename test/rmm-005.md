# RMM-005 部署与验收

状态为待完整验收。2026-11-08 新版部署后已完成 Windows 与两台 Linux 的 11 个真实任务，覆盖核心执行、平台过滤及占用恢复链路；运行中等待提示问题已本地修复、待重新部署复查，权限、运维恢复、管理员实际解除及导入边界等仍未完整覆盖。结果与条件见 [实测记录](rmm-005-results-2026-11-08.md)。先完成单设备验收，再测试批量入口。

## 部署准备

1. 构建并部署同一提交的 Web 与 MeshCentral 镜像。服务端保持 MeshCentral 1.1.54，并使用仓库的 Node.js 22 镜像。
2. 默认配置已启用 `rmm`。如果测试部署的 MeshCentral YAML 覆盖了插件列表，确认列表仍包含 `rmm` 和环境需要的其他插件。示例配置如下。

   ```yaml
   settings:
     plugins:
       enabled: true
       list:
         - jsonauth
         - utils
         - rmm
   ```

3. 确认数据目录可写并挂载持久化卷。插件在其中创建 `rmm.sqlite`。停止服务后备份该数据库及同目录下存在的 SQLite 日志文件。
4. 测试 API 地址为 [mesh.xiaonext.com](https://mesh.xiaonext.com)。开始前确认它指向本次部署，并准备站点管理员、有部分设备远程命令权限的运维账号和无命令权限账号。准备在线 Windows、两台 xiao Linux 和可控离线设备。五台并发实测仍需五台在线、匹配脚本平台的设备，不能用三个设备推断通过。认证信息通过本地配置提供。
5. 建立独立测试设备组。脚本由目标平台的 Agent 服务账号运行，不提升权限。Windows 使用 PowerShell，包装器为子进程指定执行策略；Linux 使用 `/bin/sh`，目标需有 `mktemp`、`base64 -d`、`head -c`、`cat`、`wc`、`tr` 和 `rm`。缺少准备工具时返回失败，不能标为成功。

升级前暂停新任务，核实测试设备没有遗留远端进程，停止服务并备份数据库，再同步部署 Web 与插件。新版本为升级时仍为运行中的记录保留设备占用，并将执行状态改为结果未知；历史超时记录不自动重建占用。回退到旧插件会失去占用保护，须先清空队列并确认所有远端执行已结束。不要通过删除数据库记录解除占用。

脚本版本新增 `platform` 字段，未设置的旧版本继续按 Windows 执行；新建 Linux 脚本必须明确选择 Linux。平台是脚本版本的一部分，编辑新版不会改变旧任务的执行平台。Web 与插件必须同版部署；旧插件不理解 Linux 平台，不能在回退后继续受理 Linux 任务。

历史搜索、版本历史/对比及版本化标签需同步部署新 Web 和插件。旧版本缺省没有标签；旧插件保存脚本会丢弃标签，回退前须备份并停止脚本编辑。任务搜索仅覆盖未被保留策略清理的记录，状态筛选仅考虑当前账号可见设备；空页仍可能存在下一页。

第三阶段待真实环境验收：创建带标签的多版本脚本，验证旧版本标签和任务不变、标签筛选及跨页版本对比；普通账号不得看到正文或归档脚本。创建超过 25 条任务，验证历史名称/发起人/ID 搜索、状态筛选翻页和空页继续翻页；使用部分设备权限账号确认不可见设备的状态不会影响结果，切换权限后重新查询。验证跨域访问及新旧插件不匹配时的明确错误。

## Linux 验收（本轮新增）

在脚本库新建 Linux 脚本 `RMM Linux Verify`，沿用下文四种参数 `Value`、`Code`、`Enabled` 和 `Mode`。Linux 通过 `RMM_PARAM_<参数名>` 环境变量传递参数，保留参数名大小写，整数为十进制，布尔值为 `true` / `false`，枚举为原始字符串。脚本必须引用变量，不使用 `eval`。示例只输出文字并退出：

```sh
sleep 10
printf 'VALUE=%s ENABLED=%s MODE=%s\n' "$RMM_PARAM_Value" "$RMM_PARAM_Enabled" "$RMM_PARAM_Mode"
exit "$RMM_PARAM_Code"
```

- 分别选两台 xiao 执行成功、非零退出、中文及引号、美元符、反引号、换行等字面参数；核对退出码、输出、发起人及 Linux 平台。关闭浏览器后任务继续，重新登录后可查。
- 使用 `printf 'RMM acceptance error\n' >&2; exit 1` 验证错误输出；使用 `i=0; while [ "$i" -lt 12000 ]; do printf '验'; i=$((i+1)); done` 验证 32 KiB 截断及 UTF-8 末尾完整性。
- 创建 `.sh` 文件，从本地上传及两个服务端文件导入入口保存，确认自动选择 Linux、文件名去除 `.sh` 后缀、正文正确；补测 BOM、无效 UTF-8、64 KiB 和超限边界。`.ps1` 继续选择 Windows。Linux 源文件规范化 CRLF 为 LF 后执行，NUL 字节被拒绝。
- 同选 Linux 和 Windows，Linux 脚本只派发 Linux；Windows 脚本只派发 Windows。平台不匹配设备在预览标为不支持，最终未执行。检查平台编辑产生新版本后，旧任务仍使用旧版本平台。
- Linux 上使用 `sleep 310; printf 'late receipt\n'` 重复下节占用验收；两台 Linux 可验证两设备并行及同设备串行，不能替代五台并发上限实测。
- 两个平台共用服务端权限、占用、审计、暂停、重启恢复及保留期规则；在隔离环境补测相应场景。Linux Shell 本地测试不代表真实 Agent 已验收。

## 设备占用修复验收

1. 在一台在线 Windows 上执行延时 310 秒的脚本，运行中再提交只输出文字的短脚本。五分钟后首任务为超时，后续任务仍待执行，显示“远端状态未知，后续任务等待确认”。占用继续计入全局五个执行名额；其他设备在剩余名额内仍可执行。
2. 若收到首任务的可信结束回执，占用自动解除，短脚本随后执行成功；首任务仍保持超时。记录回执关联证据，不能仅凭等待时间断言已收到回执。
3. 无结束回执时，管理员先在隔离设备核实远端进程已经结束，再从超时任务或该设备待执行任务详情选择“解除设备占用”，勾选确认并填写原因。解除后短脚本应成功，审计包含操作者、设备、执行 ID、时间及原因。
4. 普通运维账号不可解除；无设备权限或跨域请求被拒绝。旧页面解除请求不能解除新任务的占用；重复解除没有副作用。Agent 重连不能自动解除。
5. 占用与待执行记录同时存在时重启测试服务；占用保留，运行中任务改为结果未知，队列恢复但被占用设备不派发。验证迟到回执或管理员解除后可继续执行。

解除动作不停止远端脚本，不自动重试；无法确认进程结束时继续保留占用。未知占用可长期保留，即使关联历史已超过 90 天被清理；此时为该设备提交任务后，可在其等待详情中核对占用执行 ID，并由管理员确认后解除。

## 第一阶段 · 单设备与回执

在脚本库创建 `RMM Verify`，定义字符串参数 `Value`、整数 `Code`、布尔值 `Enabled` 和枚举 `Mode`，枚举取值为 `check` 和 `report`。正文使用下列只输出文字的脚本。

```powershell
param([string]$Value, [int]$Code, [bool]$Enabled, [string]$Mode)
Start-Sleep -Seconds 10
Write-Output ('VALUE={0} ENABLED={1} MODE={2}' -f $Value, $Enabled, $Mode)
exit $Code
```

| 场景             | 操作                                                                                            | 预期                                                                             |
| ---------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 关页后成功       | 选一台 Windows Agent，输入 Code 为 0、Enabled 为 true，确认后关闭浏览器。等待 15 秒后重新登录。 | 原任务继续，详情显示成功、退出码 0、设备输出和发起人。                           |
| 非零退出         | 对同一设备填写 Code 为 7、Enabled 为 false。Value 填包含引号和 PowerShell 元字符的普通文本。    | 显示失败、退出码 7。参数按字面值处理。                                           |
| 远端错误         | 执行 `throw 'RMM acceptance error'`。                                                           | 显示失败并保存诊断输出。                                                         |
| Agent 忙或丢回执 | 先用隔离设备运行一个延时命令，或在 RMM 派发后断开 Agent。                                       | 普通控制台消息不会完成任务。无结构化回执时，达到五分钟后显示超时及远端状态提示。 |
| 输出截断         | 执行 `Write-Output ('验' * 40000); exit 0`。                                                    | 显示退出码 0 和截断提示。保存的输出不超过 32 KiB，末尾没有残缺 UTF-8 字符。      |

记录服务端镜像版本、Agent 版本、任务 ID 和退出码。单设备回执失败时，先确认插件已启动、设备在线且是支持的 Windows Agent，再检查回执类型和关联标识。记录中避免收集会话 Cookie、业务数据及完整控制帧。

| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| 查找与预览         | 脚本库按名称、说明、平台、来源和归档状态筛选；预览核对可执行及各未执行原因数量，返回修改后须重新预览。确认时服务端仍重新检查权限及设备状态。                             |
| 任务筛选           | 脚本任务按名称、发起人、ID 和设备结果状态筛选，确认提示仅筛选当前页且上一页/下一页仍可用；详情按设备结果筛选。区分服务端脚本任务与浏览器本地任务。                       |
| 脚本详情与确认     | 从名称打开详情，核对平台、版本、参数和正文；非管理员无法查看未返回的正文，归档脚本不能执行。确认预览核对参数值；模拟提交响应不确定时用相同请求重试，避免重复执行。       |
| 设备输出           | 任务详情搜索设备及筛选需关注结果，打开设备输出；分别核对无输出、空输出、截断提示和复制失败提示，筛选或权限变化后不显示已不可见设备输出。                                 |
| 目标与部分失败     | 混合选择设备组与组内设备，确认预览去重。选择在线、离线和不兼容设备，查看逐设备状态及设备详情链接。已记录为未执行的离线设备上线后不会补跑。                               |
| 两个入口与本地回归 | 分别从脚本库和设备列表提交。全局任务中心的「脚本执行」能查看结果，「本地任务」仍能查看现有任务。                                                                         |

| 恢复与迟到结果     | 同时存在待执行和运行中记录时重启服务。待执行记录恢复调度，已派发且缺回执的记录变为结果未知，设备侧没有自动重放。迟到回执不得覆盖终态。                                   |
| 暂停与备份         | 在 MeshCentral 进程环境设置 `MESHCENTRAL_RMM_PAUSED=1` 后重启，确认暂停新任务受理及队列派发。验证数据库备份恢复后历史可查询，再取消暂停。                                |
| 保留期             | 在测试副本中验证维护周期。超过 30 天清除输出，超过 90 天清理任务及审计元数据。                                                                                           |

## 本地检查与记录

脚本弹窗的 UI 回归同时检查：新建/编辑脚本的基本信息与代码双栏、参数区和导入区；执行弹窗的步骤提示、脚本版本/平台摘要、设备选择标签，以及预览中可执行和跳过原因的状态标签。窄屏应收为单栏，长内容在弹窗内滚动，底部操作按钮保持可达；视觉调整不改变保存、预览或提交协议。

任务详情的 UI 回归检查任务摘要卡、各状态数量卡、设备结果筛选及表格、独立输出区和折叠审计表。筛选设备时顶部状态数量仍为当前有权查看的完整任务统计；输出空值、截断、复制失败、权限变化隐藏以及解除占用确认流程保持原有语义。窄屏检查摘要换行和表格横向滚动。

在仓库根目录对 `@meshcentral/plugins`、`@meshcentral/control-client`、`@meshcentral/shared-state` 和 `@meshcentral/web` 执行各自的 `typecheck`、`lint`、`test`，再执行 `pnpm build:web`。记录命令、结果、失败原因和未覆盖场景。验收通过后回填 [RMM 建设计划](../tasks/rmm-capabilities.md) 的状态。

Linux 主机的包装器测试直接使用 `/bin/sh`。在 Windows 验证时，先将 `RMM_TEST_SH` 设置为本机兼容 POSIX 的 `sh.exe` 绝对路径，再执行插件测试；没有 Shell 时相关执行测试会跳过。兼容 Shell、模拟 Agent 和临时数据库测试均不能替代真实 Linux/Windows Agent 验收。
