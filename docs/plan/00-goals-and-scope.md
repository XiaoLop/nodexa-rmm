# 目标、范围与成功标准

## 1. 背景

当前 `@meshcentral/shared-state` 同时承担以下职责：

- WebSocket 创建与生命周期管理；
- 鉴权、连接超时、心跳和自动重连；
- 请求发送、`responseid` 关联和超时处理；
- MeshCentral 消息解析和数据标准化；
- Zustand vanilla Store；
- React Hook 与 selector；
- 设备、分组、事件和用户信息缓存。

这种结构使控制客户端必须持有 Store，并在收到消息后直接产生和应用状态 Mutation。结果是客户端无法脱离 Zustand 独立使用，协议层也被状态更新模型限制。

## 2. 实现目标

创建独立包 `@meshcentral/control-client`，作为无框架依赖的控制通道 SDK。

该包负责：

1. 创建和关闭控制 WebSocket；
2. 处理鉴权、连接超时、心跳和自动重连；
3. 统一管理请求、响应、超时和连接关闭；
4. 解析服务端实时推送并产生标准化事件；
5. 提供设备、分组、事件等资源方法；
6. 保留通用 `request` 与 `send` 能力；
7. 通过回调和动态订阅通知外部；
8. 允许注入 WebSocket 工厂，兼容浏览器、React Native 和测试环境。

调整 `@meshcentral/shared-state`，使其只负责：

1. Zustand vanilla Store；
2. 设备、分组、事件和用户信息缓存；
3. selector 与 React Hook；
4. 将控制客户端的结果和事件映射到 Store；
5. 管理重连后的状态重新同步策略。

## 3. 非目标

本轮不包含：

- 重写 `@meshcentral/relay`；
- 实现远程桌面、文件或终端协议；
- 更换 Zustand；
- 改变 Web 和 App 的页面设计；
- 改变现有登录凭据保存策略；
- 一次性封装所有 MeshCentral action；
- 将设备、分组或事件缓存搬进控制客户端；
- 创建单独的第三个协议包；
- 在拆包阶段主动改变服务端通信格式。

如后续协议规模明显增长，可再把控制客户端内部的协议模块独立为第三个包，但不属于本次计划。

## 4. 核心边界

### 4.1 客户端可以维护的状态

| 状态 | 是否允许 | 原因 |
| --- | --- | --- |
| WebSocket 实例 | 是 | 连接基础设施 |
| 当前连接阶段 | 是 | 生命周期管理所需 |
| 等待响应的请求 | 是 | 请求关联所需 |
| 心跳和重连定时器 | 是 | 连接可靠性所需 |
| 重连次数 | 是 | 退避策略所需 |
| 设备列表缓存 | 否 | 属于应用状态 |
| 分组列表缓存 | 否 | 属于应用状态 |
| 历史事件列表 | 否 | 属于应用状态 |
| 当前页面选择 | 否 | 属于 UI 状态 |

### 4.2 状态包不得承担的职责

- 不直接创建 WebSocket；
- 不生成 `responseid`；
- 不处理心跳；
- 不实现重连定时器；
- 不解析原始 JSON 字符串；
- 不持有协议兼容分支；
- 不向服务端直接发送 MeshCentral action。

## 5. 兼容性目标

拆分后必须保持：

- Web 和 React Native 均可创建同一种控制客户端；
- 现有鉴权初始化信号仍能正确判断连接成功；
- 现有退避重连行为保持一致；
- `authcookie` 无 `responseid` 时仍按顺序安全关联；
- `getsysinfo` 无 `responseid` 时仍可按 action 和设备 ID 关联；
- `nodeconnect + conn=0` 仍标准化为设备离线；
- `changenode` 更新设备数据但不写入事件历史；
- `ifchange` 仍可由状态策略忽略；
- Relay 所需的 `request` 和 `send` 能力保持结构兼容。

## 6. 成功标准

### 6.1 架构标准

- 新包运行时依赖中不包含 Zustand 和 React；
- 控制客户端构造参数中不再出现 Store；
- 控制客户端源码不导入状态包；
- 协议解析输出业务数据或客户端事件，不输出 Zustand Mutation；
- 状态包通过独立绑定器连接 Client 与 Store。

### 6.2 功能标准

- 连接、断开、销毁、鉴权、心跳和重连正常；
- 请求超时、服务端错误和连接关闭有明确错误类型；
- 可以获取设备、分组、设备系统信息和历史事件；
- 可以修改设备以及创建、修改、删除分组；
- 可以订阅设备在线、离线、属性变化和审计事件；
- Web 与 App 的登录、退出、重连和数据展示行为不回退；
- Relay 创建会话和批量上传不受影响。

### 6.3 工程标准

以下工作区命令全部通过：

- lint；
- typecheck；
- test；
- build；
- format check。

## 7. 完成定义

只有同时满足以下条件，拆包才算完成：

1. Web 与 App 不再从状态包导入控制客户端类和客户端错误；
2. 状态包中不再保留旧客户端实现；
3. 新包拥有连接、请求、协议和资源 API 的独立测试；
4. 状态包测试不再通过协议适配器直接生成 Mutation；
5. 文档和 README 已更新为新的依赖与使用方式；
6. 全仓验证通过；
7. 旧导出已删除，或有明确的兼容期和删除日期。
