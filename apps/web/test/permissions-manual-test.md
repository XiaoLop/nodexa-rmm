# Web 权限控制手工测试指南

本文用于验证 Web 控制台的权限隐藏、禁用、路由拦截和批量目标过滤行为。

测试结果只代表前端交互控制是否符合预期。所有写操作仍应由 MeshCentral 执行最终授权，测试时必须同时确认服务端拒绝未授权请求。

## 1. 当前验证范围

当前版本已接入以下权限控制：

- 侧栏菜单：用户管理、用户组、审计日志、设置。
- 路由：用户管理、用户详情、用户组、用户组详情、审计日志、设置。
- 设备列表：文件、执行命令、编辑、删除、唤醒、重启、休眠和关机。
- 批量操作：命令、文件上传、唤醒和电源操作的有效目标过滤。
- 设备工作台：远程桌面、终端和文件管理页签。
- 设备权限来源：优先使用服务端返回的 `effectiveRights` / `meshrights`；缺失时可识别全站管理员，并合并设备组、用户组和单设备 `links` 授权。
- 站点限制：添加设备、新建设备组。
- 运行状态：控制通道断开、设备离线、Agent 能力缺失时禁用功能。

以下内容尚未完整接入，不应在本轮验收中判定完成：

- 用户和用户组页面内每一个编辑按钮的细粒度能力控制。
- 文件面板内部上传、覆盖、移动、删除等写操作的独立只读权限。
- 远程桌面内部所有输入和剪贴板控件的完整能力迁移。`RemoteViewOnly` 已限制键盘、鼠标和剪贴板写入，但 `DesktopLimitedInput` 尚未按独立能力完整落实。
- 权限来源解释，包括直接授权、用户组继承、单设备授权和 `removeRights` 的逐项展示。
- 工作台页签与桌面、终端、文件面板尚未完全共用同一份回退权限结果。当设备快照缺少 `effectiveRights` / `meshrights`、仅依赖 `links` 回退时，不应将面板内部行为或 Relay 隔离判定为完成。
- 单设备命令当前只在菜单层执行前端能力控制，命令处理入口和弹窗内部没有再次检查 `RemoteCommand`。
- 真实审计页面。目前审计路由只验证菜单与路由权限。

## 2. 测试环境准备

### 2.1 设备准备

至少准备以下两台设备，建议放入单独的测试设备组 `权限测试组`：

| 设备               | 状态           | 用途                                 |
| ------------------ | -------------- | ------------------------------------ |
| `perm-online-win`  | MeshAgent 在线 | 验证桌面、终端、文件、命令和电源操作 |
| `perm-offline-win` | MeshAgent 离线 | 验证有权限但设备离线时的禁用状态     |

在线设备建议使用 Windows Agent，并确认 MeshCentral 返回：

- `conn & 1` 不为 `0`。
- `agent.caps` 包含桌面、终端和文件能力。
- 推荐测试值为 `caps & 1`、`caps & 2`、`caps & 4` 均不为 `0`。

如果需要验证 Agent 能力缺失，可额外准备一台不包含对应 `caps` 位的 Agent。不要通过浏览器临时修改响应数据代替真实协议验证。

### 2.2 创建账号的位置

使用 MeshCentral 全站管理员账号创建测试用户，并在 MeshCentral 原生用户管理界面配置：

1. 用户的站点权限 `siteadmin`。
2. 用户对 `权限测试组` 的设备组权限。
3. 如需验证继承，再将用户加入测试用户组，并把设备组权限授予该用户组。
4. 每次修改权限后退出测试账号并重新登录，避免旧 WebSocket 快照影响结果。

不要给测试账号复用生产设备组或生产管理员权限。

本轮完整验收应优先确认 `nodes` 响应中包含服务端计算后的 `effectiveRights` 或 `meshrights`。如果设备快照没有这两个字段，只能验证页签和设备列表的回退门控；桌面、终端、文件面板的内部行为需要单独记录为已知限制。

## 3. 建议测试账号

建议创建以下五个账号。账号名称可以调整，但每个权限组合应保持一致。

### 3.1 `perm-admin`：全站管理员基线

站点权限：

```text
siteadmin = 0xFFFFFFFF
```

设备组权限：全部权限。

预期结果：

- 显示用户管理、用户组、审计日志和设置菜单。
- 可以直接访问对应管理路由。
- 显示添加设备和新建设备组按钮。
- 在线设备显示桌面、终端、文件以及全部设备操作。
- 离线设备的在线会话类操作显示但禁用。

该账号用于确认环境和设备能力正常，不用于验证最小权限。

### 3.2 `perm-restricted-viewer`：受限桌面只读账号

站点权限：

```text
NoNewGroups  = 0x00000040
NoNewDevices = 0x00001000
siteadmin    = 0x00001040
```

设备组权限：

```text
RemoteControl = 0x00000008
RemoteViewOnly = 0x00000100
NoTerminal     = 0x00000200
NoFiles        = 0x00000400
最终组合        = 0x00000708
```

预期侧栏和路由：

- 隐藏用户管理、用户组、审计日志和设置菜单。
- 仍显示仪表盘、所有设备、设备分组和实时事件。
- 直接访问 `/admin/users`、`/admin/roles`、`/monitoring/audit`、`/settings` 时显示 `403 无权访问`。

预期设备列表：

- 添加设备按钮禁用。
- 文件快捷按钮隐藏。
- 操作菜单中不显示执行命令、编辑、删除、唤醒和电源操作。
- 工作台按钮仍显示，可以进入设备概览。

预期设备工作台：

- 在线设备显示远程桌面页签。
- 终端和文件管理页签隐藏。
- 远程桌面可以建立查看会话。
- 键盘、鼠标控制和剪贴板写入不得可用。
- 手工输入 `?tab=terminal` 或 `?tab=files` 后应自动回到概览。

### 3.3 `perm-operator`：日常运维账号

站点权限：

```text
NoNewGroups  = 0x00000040
NoNewDevices = 0x00001000
siteadmin    = 0x00001040
```

设备组权限：

```text
ManageComputers = 0x00000004
RemoteControl   = 0x00000008
WakeDevice      = 0x00000040
RemoteCommand   = 0x00020000
ResetOff        = 0x00040000
最终组合          = 0x0006004C
```

不要授予：

```text
Uninstall = 0x00008000
```

预期结果：

- 管理类菜单与路由表现和受限账号相同。
- 添加设备和新建设备组按钮禁用。
- 在线设备显示并启用远程桌面、终端和文件管理。
- 操作菜单显示执行命令、编辑、唤醒、重启、休眠和关机。
- 删除操作隐藏，因为没有 `Uninstall` 权限。
- 选择在线设备后，批量命令、批量上传和电源操作可用。
- 选择在线与离线设备混合执行批量电源操作时，确认框应说明部分设备被跳过。

### 3.4 `perm-device-manager`：设备管理但不能远程控制

站点权限：

```text
NoNewGroups  = 0x00000040
NoNewDevices = 0x00001000
siteadmin    = 0x00001040
```

设备组权限：

```text
ManageComputers = 0x00000004
Uninstall       = 0x00008000
最终组合          = 0x00008004
```

预期结果：

- 文件快捷按钮隐藏。
- 工作台可以进入概览，但远程桌面、终端和文件管理页签隐藏。
- 在线设备操作菜单显示编辑和删除。
- 不显示命令、唤醒和电源操作。
- 离线设备的编辑仍可用。
- 离线设备的删除显示但禁用，因为当前实现要求 Agent 在线。

### 3.5 `perm-site-manager`：站点管理权限组合账号

站点权限：

```text
ManageUsers     = 0x00000002
ManageUserGroups = 0x00000100
AllEvents       = 0x00000800
NoNewGroups     = 0x00000040
NoNewDevices    = 0x00001000
siteadmin       = 0x00001942
```

设备组权限可以设置为只读或不分配，本账号主要验证站点菜单。

预期结果：

- 显示用户管理、用户组和审计日志菜单。
- 隐藏设置菜单，因为设置当前仅允许全站管理员访问。
- `/admin/users`、`/admin/roles` 和 `/monitoring/audit` 不显示 `403`。
- `/settings` 显示 `403 无权访问`。
- 添加设备和新建设备组按钮禁用。

## 4. 重要权限规则

### 4.1 `siteadmin = 0` 的注意事项

当前能力模型中，`NoNewGroups` 和 `NoNewDevices` 是反向限制位。因此：

```text
siteadmin = 0
```

表示账号没有用户管理、用户组管理、全部事件和设置权限，但不会自动禁用添加设备或新建设备组。

要验证这两个按钮被禁用，必须显式设置：

```text
NoNewGroups | NoNewDevices = 0x00001040
```

### 4.2 隐藏和禁用的区别

- 没有权限：功能应隐藏。
- 有权限但网关断开：功能应显示但禁用，原因是“控制通道未连接”。
- 有权限但设备离线：会话类功能应显示但禁用，原因是“设备当前离线”。
- 有权限但 Agent 不支持对应能力：功能应显示但禁用，原因是“设备 Agent 不支持此功能”。
- 设备权限数据尚未返回或无法在客户端安全计算：设备功能应显示但禁用，原因是“正在确认设备权限”。

“正在确认设备权限”只适用于设备级能力。站点级能力目前没有独立的加载状态；`siteadmin` 缺失时按 `0` 处理。由于 `NoNewGroups` 和 `NoNewDevices` 是反向限制位，测试添加设备和新建设备组前必须先确认 `userinfo` 已加载完成。

### 4.3 设备有效权限来源

设备能力按以下优先级计算：

1. 如果设备包含 `effectiveRights` 或 `meshrights`，直接使用服务端计算结果。
2. 如果服务端结果缺失，且 `siteadmin` 是 `0xFFFFFFFF`，按全站管理员处理。
3. 普通用户合并设备组 `mesh.links` 中的用户直接授权和用户组授权。
4. 在设备组权限基础上，继续合并设备 `node.links` 中的用户直接授权和用户组授权。
5. 如果没有任何有效权限来源，保持“正在确认设备权限”，不能把数据缺失解释为明确无权限。

如果 `userinfo.removeRights` 为非零，且设备没有服务端返回的最终有效权限，客户端不会自行执行简化的按位扣减，而是保持“正在确认设备权限”。`removeRights` 的具体结果只能以服务端返回的最终权限和服务端实际鉴权为准。

## 5. 手工测试步骤

### 5.1 侧栏菜单测试

对每个测试账号执行：

1. 登录 Web 控制台。
2. 记录侧栏中是否显示用户管理、用户组、审计日志和设置。
3. 与账号的站点权限矩阵对照。
4. 刷新页面，再次确认菜单结果不变。
5. 退出后登录其他账号，确认菜单不会保留上一个账号的结果。

### 5.2 路由直达测试

普通或受限账号登录后，分别直接访问：

```text
/admin/users
/admin/users/<任意用户ID>
/admin/roles
/admin/roles/<任意用户组ID>
/monitoring/audit
/settings
```

预期：

- 缺少相应能力时显示 `403 无权访问`。
- 拥有能力时进入目标页面或当前占位页面。
- 不得只依赖侧栏隐藏，直接输入 URL 不能绕过守卫。

### 5.3 设备列表单设备操作测试

对在线设备打开操作菜单并检查：

| 操作           | 所需设备权限                     | 无权限 | 有权限且在线 | 有权限但离线         |
| -------------- | -------------------------------- | ------ | ------------ | -------------------- |
| 文件快捷入口   | `RemoteControl` 且没有 `NoFiles` | 隐藏   | 启用         | 禁用                 |
| 执行命令       | `RemoteCommand`                  | 隐藏   | 启用         | 禁用                 |
| 编辑           | `ManageComputers`                | 隐藏   | 启用         | 启用                 |
| 删除           | `Uninstall`                      | 隐藏   | 启用         | 禁用                 |
| 唤醒           | `WakeDevice`                     | 隐藏   | 启用         | 启用                 |
| 重启/休眠/关机 | `ResetOff`                       | 隐藏   | 启用         | 禁用，AMT 在线时除外 |

同时确认：

- 禁用的文件按钮悬停时显示禁用原因。
- 没有任何菜单操作权限时，三点操作按钮不显示。
- 电源、编辑和删除操作即使绕过按钮状态触发处理函数，函数入口也应再次阻止无权操作。
- 单设备命令当前只在菜单层禁用。通过开发者工具绕过菜单状态时，前端不保证再次阻止，必须验证 MeshCentral 服务端拒绝无权限命令。

### 5.4 设备工作台测试

依次验证以下权限组合：

| 权限组合                              | 桌面页签       | 终端页签 | 文件页签 |
| ------------------------------------- | -------------- | -------- | -------- |
| 无 `RemoteControl`                    | 隐藏           | 隐藏     | 隐藏     |
| `RemoteControl`                       | 显示           | 显示     | 显示     |
| `RemoteControl + RemoteViewOnly`      | 显示，只读     | 显示     | 显示     |
| `RemoteControl + DesktopLimitedInput` | 显示，有限输入 | 显示     | 显示     |
| `RemoteControl + NoDesktop`           | 隐藏           | 显示     | 显示     |
| `RemoteControl + NoTerminal`          | 显示           | 隐藏     | 显示     |
| `RemoteControl + NoFiles`             | 显示           | 显示     | 隐藏     |

对每个隐藏页签直接修改 URL：

```text
/devices/<设备ID>/workspace?tab=desktop
/devices/<设备ID>/workspace?tab=terminal
/devices/<设备ID>/workspace?tab=files
```

当设备快照包含服务端 `effectiveRights` / `meshrights` 时，预期自动回到概览，且不建立 Relay 会话。

当页签权限仅由设备组、用户组或单设备 `links` 回退得出时，当前页签门控与面板内部仍可能使用不同的权限来源。此时应记录实际是否建立 Relay，但暂不将“绝不建立 Relay”作为通过标准。

远程桌面输入需要额外确认：

- `RemoteViewOnly`：键盘、鼠标、Ctrl+Alt+Del 和本地剪贴板写入远端不可用；读取远端剪贴板到本地可以保留。
- `DesktopLimitedInput`：当前实现尚未完整落实独立的输入和剪贴板能力，可能仍允许完整键鼠与剪贴板写入。该项记录为已知缺陷，不判定通过。

再停止在线设备的 MeshAgent：

- 有权限的页签仍显示。
- 页签变为禁用。
- 悬停提示“设备当前离线”。
- AMT 在线时，桌面和终端是否仍可用取决于 AMT 状态。

### 5.5 批量操作测试

选择权限和状态混合的设备，例如：

- 1 台在线且有权限。
- 1 台离线但有权限。
- 1 台在线但无对应权限。

验证：

1. 批量命令仅在至少一台设备的 `RemoteCommand` 能力可执行时启用。
2. 批量上传仅将文件能力可执行的设备加入任务。
3. 批量唤醒仅处理具备 `WakeDevice` 权限的设备。
4. 批量电源仅处理具备 `ResetOff` 且 Agent 或 AMT 在线的设备。
5. 批量唤醒和电源操作的确认框显示被跳过设备数量。
6. 当没有任何有效目标时，对应菜单项禁用。

批量命令和批量上传会在打开弹窗前过滤无权限或当前不可用的设备，弹窗只保证显示有效目标，不保证显示因权限过滤而跳过的数量。测试时应分别记录已选设备数量和实际目标数量。

注意：当前“移动分组”尚未接入本轮统一设备权限过滤，应单独记录为剩余项，不要误判为通过。

### 5.6 网关断开测试

使用具备完整设备权限的账号：

1. 登录并打开设备列表或设备工作台。
2. 停止开发代理、断开网络，或关闭 MeshCentral 控制 WebSocket。
3. 保持页面不刷新，观察按钮和页签。

预期：

- 原本有权限的功能保留可见性。
- 依赖控制通道的功能变为禁用。
- 禁用原因显示“控制通道未连接”。
- 恢复连接并同步快照后，功能重新启用。

## 6. 服务端授权验证

前端隐藏和禁用不是安全边界。每个高风险操作至少做一次服务端拒绝验证：

1. 使用无权限账号登录。
2. 通过浏览器开发者工具或独立 WebSocket 测试工具构造对应 MeshCentral 请求。
3. 确认 MeshCentral 返回拒绝、关闭请求或不执行操作。
4. 确认设备、用户、文件和电源状态没有发生变化。
5. 记录 MeshCentral 版本、请求摘要和返回结果，敏感字段必须脱敏。

重点验证：

- 删除设备。
- 远程命令。
- 电源操作。
- 文件写入和删除。
- 用户及用户组修改。
- 权限修改。

```md
| 执行命令             | 隐藏/禁用/启用 |      |           |            |
| 编辑设备             | 隐藏/禁用/启用 |      |           |            |
| 删除设备             | 隐藏/禁用/启用 |      |           |            |

```

## 8. 通过标准

本轮权限控制验收通过需要同时满足：

- 所有测试账号的侧栏结果与站点权限一致。
- 所有受保护路由无法通过直接 URL 绕过。
- 无设备权限的操作隐藏。
- 有权限但设备、Agent 或网关条件不足的操作禁用并显示正确原因。
- 当设备快照包含服务端最终有效权限时，工作台隐藏页签不能通过查询参数绕过，且不得建立对应 Relay。
- 仅依赖 `links` 回退时，页签门控应正确；面板内部权限和 Relay 隔离作为已知限制单独记录。
- 批量操作只处理当前可执行的目标设备。
- MeshCentral 拒绝所有无权限写请求。
- 切换账号、刷新页面和断线重连后权限状态不会串号或保留旧值。
- 测试记录包含账号权限、设备状态、实际结果和必要证据。

以下项目不阻断本轮其余权限能力验收，但必须记录为已知限制：

- `DesktopLimitedInput` 的键鼠和剪贴板细粒度控制。
- 单设备命令处理入口的前端二次权限复核。
- 仅依赖 `links` 回退时，工作台面板内部与页签权限来源不一致。
- 批量命令和批量上传不展示统一的权限过滤跳过数量。
